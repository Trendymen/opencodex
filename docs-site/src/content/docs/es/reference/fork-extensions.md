Este apéndice describe las funciones que el Fork de Trendymen añade al proyecto original. Las demás páginas de referencia conservan el texto original; las diferencias de configuración están en [Configuración del Fork](/es/reference/configuration/fork-extensions/).

<a id="compatibility-changes"></a>

## Cambios de compatibilidad

- Los detalles del registro distinguen el esfuerzo inicial de nivel superior de Responses enviado por el cliente de la última `configuration_update` reconocible en su entrada inicial; la columna de esfuerzo de la lista sigue la presentación del proyecto original. Si una continuación no tiene una actualización visible o una actualización posterior no se reconoce, el valor de sesión aparece como desconocido; no se infiere el historial oculto. Esta observación no demuestra que el ajuste se haya reenviado ni que el proveedor lo haya aplicado. Los fotogramas WebSocket posteriores pueden cambiar la configuración y quedan fuera de la observación inicial.
- La reescritura de identidad de cuentas Pool escapa los caracteres de turn metadata superiores a U+00FF antes de escribir encabezados HTTP, y conserva los caracteres Latin-1 válidos y los valores JSON. Esto evita errores locales en encabezados con caracteres chinos o emoji; el aislamiento de identidad de la cuenta sigue vigente cuando se desactiva el procesamiento de compatibilidad.
- Las solicitudes nativas de Responses con suscripción oficial de GPT tienen 23 permisos de procesamiento por proveedor, todos activados de forma predeterminada. Cubren la compatibilidad de solicitudes y respuestas, los encabezados generados y errores locales opcionales, incluidas las cuentas Direct y Pool. Siguen aplicándose las condiciones originales de cada función; los demás destinos y la entrada traducida conservan su comportamiento. Consulta [Procesamiento de suscripciones de GPT](/es/reference/configuration/fork-extensions/#gpt-subscription-processing) para ver cada control y las protecciones de recuperación, presupuesto y credenciales que se mantienen.
- Las rutas Responses de Ark GLM/Kimi y BigModel GLM adaptan los esquemas de herramientas no admitidos y las restricciones de assistant prefill. Las herramientas ordinarias de terceros eliminan las anotaciones `encrypted` exclusivas de ChatGPT, pero conservan las propiedades y los valores literales con ese nombre. Los destinos operados por OpenAI y los relay directos de confianza explícita conservan las anotaciones; los miembros de un combo no heredan esa excepción de ruta directa.
- Los adaptadores OpenAI Chat, Google, Command Code, Anthropic, Kiro y Cursor añaden indicaciones de progreso cuando se cumplen sus condiciones de herramientas. Algunos también añaden indicaciones para descubrir herramientas y ordenar parches. El catálogo de modelos y Responses nativo no las añaden automáticamente, y el modelo puede no mostrar progreso visible. La presentación de resultados de code-mode y las indicaciones del host siguen el comportamiento original; el proxy no sintetiza progreso ni ejecuta o reintenta parches.
- Las llamadas anidadas `functions.exec` / `web__run` declaradas y las finalizaciones `spawn_agent.fork_turns` admitidas reciben una reparación acotada. Se mantiene el soporte original para herramientas personalizadas enrutadas; el Fork convierte sus salidas en cadenas y combina las salidas repetidas de `call_id` que puedan relacionarse de forma segura para el destino estricto Console Go. Las declaraciones actuales de herramientas siguen definiendo la autorización.
- La inferencia de fase de Responses nativo por modelo incluye la entrega JSON ordinaria junto con la opción SSE original por proveedor. La proyección del resumen de razonamiento solo se aplica a las respuestas de adaptadores traducidos cuando el cliente la solicita. Responses nativo conserva el razonamiento del canal de contenido en SSE, JSON y las repeticiones guardadas.
- Las instrucciones de anotación usan directivas de chip sin comillas invertidas. La reparación de salida conserva los bloques de código, pero no depende del número de anotaciones de este turno ni procesa fragmentos de código en línea que ocupen varias líneas; el reenvío nativo solo reescribe la entrada cuando su permiso lo permite.
- Con los permisos de procesamiento correspondientes activados, el vaciado SSE y el tratamiento del evento terminal conservan los errores utilizables del proveedor y un único `[DONE]` final. El reenvío canónico transfiere el encabezado Lite solo al construir un fotograma WebSocket hacia el proveedor; un valor HTTP explícito tiene prioridad sobre los metadatos del mismo nombre. Los metadatos de la solicitud HTTP permanecen sin cambios.
- Los errores de cuota de Ark conservan el mensaje y la hora de restablecimiento del proveedor e impiden el reintento automático. La detección de BigModel Codex acepta `models[].slug`.

<a id="recovery-and-maintenance"></a>

## Recuperación y mantenimiento

El listener opcional de la API de modelos mantiene el servicio de administración en loopback separado de un endpoint de datos LAN en el puerto `10100`. Reutiliza las rutas y credenciales nativas de modelos, rechaza la administración y el emparejamiento en el endpoint auxiliar e informa del estado real del listener mediante una lectura local de administración verificada. Está desactivado de forma predeterminada y los cambios de topología requieren reiniciar. Consulta [Listener de la API de modelos](/es/reference/configuration/fork-extensions/#model-api-listener) para conocer las dos topologías admitidas y el límite del modo principal nativo.

La recuperación de tareas cifradas añade el tratamiento estricto de envolturas del backend, una repetición nativa acotada tras agotar los reintentos por errores 5xx transitorios y un aviso sin texto cifrado cuando agota el tiempo de espera un `MESSAGE` principal admitido. El texto cifrado ilegible es terminal: no se reenvía a rutas ordinarias de terceros ni se guarda en el estado de continuación. La recuperación sigue requiriendo activación explícita.

El Fork ofrece diagnósticos en disco, controles independientes para muestras de texto y reversión de paquete, servicio y Volta con `install:local`. Las versiones `ben.N` comparan primero la versión principal del proyecto original y después la revisión del Fork; una versión estable de la misma versión principal no sobrescribe el Fork. Los tags publicados son inmutables.

El desarrollo y los candidatos de publicación usan `dev`. Una compilación publicada se identifica por su tag inmutable del Fork y su GitHub Release formal. La validación de publicación usa la ejecución completa `workflow_dispatch` del flujo original sobre el commit exacto de `dev`; no depende de una ejecución por push a `main`.

La marca de proveedor de búsqueda web independiente, la recuperación con texto cifrado real del backend y la sustitución global y recuperación del servicio en Windows aún requieren aceptación de extremo a extremo vinculada a la implementación. Las pruebas oficiales no demuestran esos resultados.
